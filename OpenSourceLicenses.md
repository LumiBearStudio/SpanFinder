## Native Components

These ship inside `otterzip_ffi.dll`, the native archive engine that lets SPAN Finder
open `.7z`, `.tar.*`, `.cab`, `.rar` and other formats that .NET cannot read on its own.
The DLL is built from the OtterZip project; see
[`third_party/otterzip/VERSION.txt`](third_party/otterzip/VERSION.txt) for the exact
commit it was built from.

### OtterZip (archive engine core)

- **Author**: LumiBear Studio
- **Version**: v1.2.3.0
- **License**: MIT OR Apache-2.0
- **Repository**: https://github.com/LumiBearStudio/OtterZip

The Rust core under `crates/**` is dual-licensed MIT OR Apache-2.0. Apache-2.0 is
compatible with GPL-3.0, which is what allows SPAN Finder to link against it.

### UnRAR

- **Author**: Alexander Roshal (RARLAB)
- **Version**: UnRAR 7.1, as vendored by the `unrar_sys` crate
- **License**: UnRAR License (see below) — **not** an OSI-approved license
- **Homepage**: https://www.rarlab.com/rar_add.htm

SPAN Finder uses UnRAR to **extract** RAR archives only. SPAN Finder never creates RAR
archives, and the UnRAR code must not be used to develop a RAR (WinRAR) compatible
archiver or to re-create the RAR compression algorithm.

Because the UnRAR license imposes that restriction on recipients, it is not compatible
with the GNU GPL. SPAN Finder is GPL-3.0-or-later, so the copyright holder grants an
explicit **UnRAR Exception** — see [LICENSE.md](LICENSE.md).

The `unrar_sys` crate vendors the upstream UnRAR release with four patches applied on
top (recorded in that crate's `vendor/patches.txt`), so the sources bundled here are a
modified version of UnRAR. The full license text below is reproduced accordingly.

### Other bundled components

`otterzip_ffi.dll` also statically links zlib-ng, bzip2/libbzip2, liblzma (XZ Utils),
Zstandard, and a number of permissively licensed Rust crates. The complete generated
notice list is maintained in the OtterZip repository as `THIRD-PARTY-NOTICES.md`:
<https://github.com/LumiBearStudio/OtterZip/blob/main/THIRD-PARTY-NOTICES.md>

Note that the same caveat applies there: for components that wrap vendored C libraries,
the crate metadata may name the wrapper's license rather than the vendored library's.
